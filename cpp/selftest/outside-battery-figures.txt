# OC-122: RECORDED PER-STREAM FIGURES FOR THE PINNED CORPUS.
#
# WHY THIS FILE EXISTS. Until now NOTHING compared this corpus's figures against
# recorded values at numerical tolerance. outside-battery-corpus.txt pins the
# BYTES by digest; the FIGURES were pinned nowhere. compareresults.pl covers the
# ELEVEN NIST datasets at 1e-10, and pin-check.sh binds ONE value for ONE NIST
# stream -- neither touches these 25. Measured consequence: a uniform +0.005
# shift in every figure here PASSES the window, PASSES the mean bound, and
# leaves pin-check and the corpus digests untouched.
#
# WHY A NUMERICAL TOLERANCE AND NOT A STATISTICAL ONE. These streams come from
# fixed seeds and the corpus is digest-pinned, so re-running reproduces the same
# bytes and the same figures. The expected run-to-run variation is ZERO. A
# 3-sigma band derived from how much DIFFERENT random streams vary is the right
# tolerance for sampling the population and the WRONG tolerance for re-running
# fixed bytes -- the same category error as demanding an independent sample of a
# deterministic quantity, inverted.
#
# THE TOLERANCE IS 1e-9 RELATIVE, matching pin-check.sh's RELTOL and
# known-platform-deltas.txt's per-row allowance, because the prediction
# estimators differ between the two supported platforms by up to 3.66e-10
# (OC-112) and a tighter bound would false-fail on x86-64. Measured headroom on
# one platform: agreement is ~1e-13, so roughly four orders.
#
# FORMAT: <stream> <binding-estimator> <figure>
# Measured on Darwin arm64 at the commit that added this file, with the
# binding estimator named so a change in WHICH estimator binds is also visible.
