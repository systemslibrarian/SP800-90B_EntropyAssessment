# Adversarial audit of `ea_non_iid` — 2026-09-30

**What this is.** A single-pass adversarial audit run by 14 automated attacker agents against this fork at `f06166f7c2de19a8a654889e702376296a3c8cc1` (upstream baseline `87c104d0ed4cbc96103e7b8b38d6f2c7e0a6b289`; every file on the `ea_non_iid` include path byte-identical between the two, so line numbers apply upstream). The planned refutation stage never ran. **Every row below is an attacker's claim unless its Status column says VERIFIED**, in which case the project owner's session re-ran the draft issue's exact commands on this fork's macOS build and quoted the real output.

**What was done with it (2026-09-30).** Three findings were spot-verified and filed upstream as separate issues; one has a pull request. Per this fork's rule (NOTICE; `docs`), nothing on `master` changes estimator behaviour: the fix lives on its own branch, is not merged here, and the pinned-output check on `master` still passes. If a fix is ever adopted here before upstream merges it, that will be a recorded decision naming the PR.

## Attacked and not broken — attacker/agent claims, unverified here


- **Spec worked examples**, run by me on the built binary: MCV (§6.3.1, 0.5363), collision (§6.3.2, X̄ 2.7143, σ̂ 0.4688, X̄' 2.3915, p 0.7329, 0.4483), Markov (§6.3.3, 0.7606 exact; the spec's 0.761 used 3-digit rounded transitions), t-tuple and LRS (§6.3.5/6.3.6 with the cutoff lowered to 3 in a scratch copy: 0.2731 and 0.6146). All reproduce to the printed digits.
- **Collision closed form**: F(q) = q(2q²+2q+1) equals the spec's Γ(3,1/q)q³e^{1/q}, and step 7 reduces to −2p²+2p+2, so the quadratic at collision_test.h:64-72 is exact; X̄' < 2 clamps to p = 1 (entropy 0) and X̄' ≥ 2.5 gives 1.0, both as the spec says; σ̂ uses v−1 as specified.
- **Independent literal implementations** by the attackers matched the tool on every estimator except where reported above: MCV (50-digit reference), Markov (44 crafted inputs), compression (mpmath; the G() rearrangement equals the spec's double sum; com_exp is monotone on [1/64,1]), t-tuple/LRS (Q, u, v, P_W on two independent implementations), Lag (trace-for-trace), MultiMCW (per-step vs an independent reference for L ≥ 4096), MultiMMC binary path, LZ78Y (binary and generic agree on 1-bit data; C matches a literal §6.3.10 implementation).
- **Confidence bounds and clamps**: every p_u is applied before −log2, clamped to [0,1], uses L−1 or N−1 as specified, sqrt arguments cannot go negative; predictors take max(1/k, P_global', P_local) as specified; the C = 0 branch 1−0.01^(1/N) matches.
- **Numerics**: no OpenMP pragma or reduction on the ea_non_iid path (only in ea_iid and ea_restart); no integer overflow within 2^31 samples except the theoretical dict[] index (F14); LRS pair counts use uint64 with an explicit overflow assert; relEpsilonEqual's ULP comparison handles sign, inf, NaN and subnormals; the collision and compression σ̂ cancellation forms do not go negative on any tested input; prediction_estimate_function asserts do not trip for reachable states; calc_p_local fallback exits never returned a p below the true P_local on tested inputs.
- **Input pipeline**: symbol translation is order-preserving and leaves every literal estimator unchanged; the bitstring is built from raw values, MSB-first, consistently; `-l` in-range reads are correct; bits_per_symbol out of range (0, 9, −1, text) is refused; a directory as input is refused; upstream's reference outputs reproduce on this build.
- **Attacks that failed to push a figure up**: masking with an under-declared width (the tool refuses rather than masks); symbol-value choice on the literal path; ties for the MCV mode; MultiMCW/Lag/LZ78Y tie-break and scoreboard order; near-uniform inputs against the compression solve's ill-conditioning; JSON vs text producing different figures (only formatting differs, F23).
