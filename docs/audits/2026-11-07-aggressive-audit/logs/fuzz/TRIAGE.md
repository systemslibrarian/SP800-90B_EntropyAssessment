## reading the classes

- EXIT:n in the san column means the authoritative build did NOT reproduce the crash (exit n, last stdout line quoted in the detail files). A crash only under the fuzz build is a Homebrew-clang-23 codegen or instrumentation artefact until shown otherwise; a crash only under the fuzz AND san builds but not production is a sanitizer-detected silent defect (the production binary runs past it) and is still a finding.
- ASSERT rows are the tool's own assert() aborts (SIGABRT). An assert reached only through the escape's decline paths (below) is not reachable by a compliant file; the tiled column is the measurement.
- TIMEOUT rows from T6 are expected for inputs that FAIL the permutation battery (all 10,000 permutations run); the hang is the battery's cost, not a loop defect, unless the tiled or 90 s re-run shows otherwise.

## what this triage cannot see (rule 18)

- A crash that depends on the exact input LENGTH or period: tiling to 1,000,000 bytes changes both, so NOT SHOWN is not NOT REACHABLE.
- A T6 crash that depends on the permutation shuffle (seed() reads /dev/urandom): it may not replay from the input alone; three re-runs were made, not thirty.
- UB classes the fuzz build traps without a message (AFL_USE_UBSAN is trap-on-error); only the san build names them.
- Anything beyond the 30/90 s caps, or beyond --max-compliant 2 tiled runs.
- If the san build was NOT FOUND, every san column is NA and the fuzz key stands in for it; re-run triage.sh --san-dir once harness/sanitizers has built.
